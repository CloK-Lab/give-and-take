A service asks for 0.01 USDC per request. In the example below, the payment
requirement names the Base Sepolia USDC token on `eip155:84532` and encodes the
amount as `"10000"` integer base units. This is testnet USDC with no dollar
redemption value. The [stablecoin discussion](../ERC20/Note.mdx#stablecoin-payments)
explains pricing and units; the payment protocol specifies how to request,
authorize, and settle the transfer.

The [wallet's authorization policy](../Wallet/Note.mdx) decides whether spending
is allowed; the payment protocol coordinates the exchange between client and
service.

## In x402

[x402](https://github.com/x402-foundation/x402) defines payment exchange over HTTP
for access to resources. At revision `7f2b2f1`, the SDK's
[`payments.ts`](https://github.com/x402-foundation/x402/blob/7f2b2f1f77fa5317615735e3378a6fad41cccb4e/typescript/packages/core/src/types/payments.ts)
defines three related objects:

- `PaymentRequired` describes the resource and lists acceptable payment options.
- `PaymentRequirements` names one option: scheme, network, asset, amount,
  recipient, timeout, and scheme-specific `extra` data.
- `PaymentPayload` carries the selected option and the client's payment data.

The amount is encoded as a decimal string of integer base units. It is not a
floating-point ETH price. The
[`exact` EVM scheme](https://github.com/x402-foundation/x402/blob/7f2b2f1f77fa5317615735e3378a6fad41cccb4e/specs/schemes/exact/scheme_exact_evm.md)
uses token-transfer authorization mechanisms. Its EIP-3009 example specifies
a USDC contract on Base Sepolia, not native ETH on Ethereum mainnet. A facilitator
submits the authorized token transfer and pays the transaction gas.

## Payment requirements

The projection retains the core fields. `NetworkId` separates the namespace
and chain reference; the source encodes them together, such as `eip155:84532`.

```lean4 file="./Model.lean" declaration="PaymentRequirements"
```

The surrounding response can offer several options for the same resource:

```lean4 file="./Model.lean" declaration="PaymentRequired"
```

This example copies the core values from the upstream EIP-3009 example:

```lean4 file="./Checks.lean" declaration="exampleRequirements"
```

`amountUnits exampleRequirements` returns `some 10000`; `"0.01"`, `"-1"`, and
`"invalid"` are rejected by the integer decoder. Turning base units into a display
amount requires the token's decimal metadata, as in the
[assets and tokens note](../ERC20/Note.mdx).

Decoding requirements does not verify a payment. In the upstream EIP-3009 flow,
verification checks the signature and authorized transfer parameters; settlement
submits the token transfer. Our projection stops at the requirements and integer
amount. It omits scheme-specific `extra`, signatures, and settlement execution.
`maxTimeoutSeconds` describes a duration; it is not itself an absolute expiry
timestamp or a transaction nonce.

The [A2A x402 extension](https://github.com/google-agentic-commerce/a2a-x402)
connects payment messages with agent interaction. A2A task completion and x402
payment settlement remain separate events.
